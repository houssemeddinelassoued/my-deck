# Atelier 4 · L’environnement Claude Code du dépôt

> Jour 2, 12 h 30 – 14 h 15 · 100 minutes · individuel · application Claude (onglet Code) ou claude.ai/code

## Objectif

Équiper le dépôt pour que Claude Code y travaille **seul et en sécurité** : mémoire du projet, permissions, une Skill, deux hooks, un serveur MCP et un sous-agent relecteur. Vous écrivez la configuration ; Claude Code fait le travail ; vous vérifiez son comportement.

## Ce que vous allez créer

| Fichier | Rôle |
|---|---|
| `CLAUDE.md` | mémoire du projet, lue à chaque session |
| `.claude/settings.json` | permissions (`allow`, `ask`, `deny`) et hooks |
| `.claude/skills/ajouter-champ/SKILL.md` | une procédure chargée à la demande |
| `.claude/hooks/bloquer-secrets.mjs` | le hook qui bloque les secrets (squelette fourni) |
| `.mcp.json` | le serveur MCP des demandes |
| `.claude/agents/relecteur-securite.md` | le sous-agent relecteur |

## Étapes

### A4.1 · Mémoire et droits (15 min)

1. Ouvrez le dépôt dans l’application Claude (onglet Code) et lancez `/init`.
2. Réduisez le `CLAUDE.md` produit à l’essentiel (80 lignes au plus) : les commandes `node guichet.mjs …`, l’architecture en une ligne, les règles que Claude ne peut pas deviner, la définition de « fini ».
3. Dans `.claude/settings.json`, des permissions : autoriser `Bash(node guichet.mjs *)` ; demander avant `git commit` ; refuser la lecture de `.env`, `git push` et `curl`.
4. Testez : « lis le fichier .env » doit être refusé.

Réussite : `node guichet.mjs verifier A4.1` · reprise : `node guichet.mjs reprise A4.1`

### A4.2 · La Skill ajouter-champ (25 min)

1. Écrivez `.claude/skills/ajouter-champ/SKILL.md` : un en-tête `name` et `description` (ce qu’elle fait **et quand l’utiliser**), puis la procédure. Indice : un champ recopié du formulaire porte `"x-source": "formulaire"` dans le contrat ; les colonnes de la base sont créées à partir du contrat.
2. **Nouvelle session**, puis : « ajoute un champ site_web facultatif ». La Skill se déclenche-t-elle ? Sinon, corrigez sa description.
3. Le champ doit aller du formulaire web jusqu’à la base.

Réussite : `node guichet.mjs verifier A4.2` · reprise : `node guichet.mjs reprise A4.2`

### A4.3 · Deux hooks (20 min)

1. Complétez `.claude/hooks/bloquer-secrets.mjs` : bloquer (code de sortie **2**, message sur stderr) l’écriture d’un fichier `.env` et tout texte qui contient un secret (réutilisez le motif `secret-en-dur` de `garde/regles.json`).
2. Dans `.claude/settings.json` : ce hook en `PreToolUse` sur `Write|Edit|MultiEdit`, et `node guichet.mjs garde --rapide` en `PostToolUse`.
3. Testez : demandez à Claude d’écrire un jeton Notion en dur dans un fichier de configuration. Il doit être bloqué et reformuler.

Réussite : `node guichet.mjs verifier A4.3` · reprise : `node guichet.mjs reprise A4.3`

### A4.4 · Le serveur MCP des demandes (15 min)

```bash
claude mcp add --scope project demandes -- node outils/mcp-demandes/serveur.mjs
```

Le serveur (fourni, lecture seule) expose `lister_demandes` et `compter_par_priorite` sur la base `donnees/guichet.db`. Relancez la session, vérifiez avec `/mcp`, puis demandez : « quelles demandes P1 sont ouvertes depuis plus de 48 h ? ». Comparez avec une requête faite en ligne de commande (`sqlite3`, si installé) : quand préférer l’un ou l’autre ?

Réussite : `node guichet.mjs verifier A4.4` · reprise : `node guichet.mjs reprise A4.4`

### A4.5 · Le relecteur et l’orchestration (25 min)

1. Créez `.claude/agents/relecteur-securite.md` : description qui dit quand l’utiliser, outils en lecture seule (`Read, Grep, Glob, Bash`), consigne « aucun constat sans preuve ».
2. Demandez à Claude d’implémenter « filtrer le tableau de bord par client » (`GET /api/demandes?client=…` et un champ de filtre dans l’interface).
3. Faites relire par le sous-agent, corrigez, puis commitez.

Réussite : `node guichet.mjs verifier A4.5` · reprise : `node guichet.mjs reprise A4.5`

## Bonus

Empaquetez Skill, sous-agent, hooks et serveur MCP dans un **plugin** pour le partager entre dépôts.

## À retenir

Un fait → `CLAUDE.md` ; une interdiction → permission ; une procédure → Skill ; un « à chaque fois » → hook ; un regard séparé → sous-agent ; un outil sans ligne de commande → MCP.
