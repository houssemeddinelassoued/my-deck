# Atelier 2 · Harnais : contrat, garde, boucle, juge, évaluation

> Jour 1, 12 h 50 – 14 h 20, puis 14 h 30 – 15 h 10 · 90 + 40 minutes · individuel

## Objectif

Construire autour de l’extraction un harnais qui **refuse** ce qui est mal formé, **bloque** le code dangereux, **fait corriger** automatiquement, **note** l’architecture… puis **mesurer** sur 12 cas de référence.

## Les fichiers de votre stack

| Rôle | TypeScript | Python | Java | .NET |
|---|---|---|---|---|
| Validation par le contrat | `ts/src/domaine/validation.ts` | `python/guichet/domaine/validation.py` | `…/domaine/Validation.java` | `dotnet/Guichet/Domaine/Validation.cs` |
| Boucle | `ts/src/outils/boucle.ts` | `python/guichet/outils/boucle.py` | `…/outils/Boucle.java` | `dotnet/Guichet/Outils/Boucle.cs` |
| Fichier écrit par la boucle | `ts/src/domaine/texte.ts` | `python/guichet/domaine/texte.py` | `…/domaine/Texte.java` | `dotnet/Guichet/Domaine/Texte.cs` |

Fichiers communs : `contrats/demande.schema.json`, `garde/regles.json`, `garde/cas/`, `prompts/juge.md`, `contrats/verdict.schema.json`.

## Étapes

### A2.1 · Le contrat (20 min)

1. Complétez `contrats/demande.schema.json` :
   - `type` : énumération `incident`, `evolution`, `devis`, `question` ; `priorite` : `P1`, `P2`, `P3` ;
   - tous les champs dans `required` (les facultatifs sont nullables : `["string", "null"]`) ;
   - `"additionalProperties": false` ; `client` non vide (`"minLength": 1`).
2. Complétez la validation de votre stack (trois trous : champ en trop, valeur hors énumération, chaîne trop courte).
3. Essayez le vrai modèle : `node guichet.mjs extraire --cas 3 --moteur claude-cli`, puis `--cas 12` : la demande incomplète doit être rejetée avec un message lisible.

Réussite : `node guichet.mjs verifier A2.1` · reprise : `node guichet.mjs reprise A2.1`

### A2.2 · La garde (25 min)

`garde/regles.json` contient deux règles (`secret-en-dur`, `reseau-non-prevu`). Ajoutez :

- `sql-concatene` : une requête SQL construite par concaténation ou interpolation (`${…}`, `" + x`, f-string Python, `$"…"` en C#) ;
- `execution-dynamique` : `eval(`, `exec(`, `new Function(`, `Runtime.getRuntime().exec`…

Chaque règle a un **nom**, un **motif** (expression régulière), des **drapeaux** (`"i"`…), un **message** et la **correction attendue**.

```bash
node guichet.mjs garde --cas     # les 4 extraits piégés doivent être attrapés
node guichet.mjs garde           # votre code ne doit déclencher aucune règle
```

Réussite : `node guichet.mjs verifier A2.2` · reprise : `node guichet.mjs reprise A2.2`

### A2.3 · La boucle générer → vérifier → corriger (30 min)

1. Complétez la boucle de votre stack (trois trous : condition de sortie, ce qu’on renvoie, le résultat d’échec). `node guichet.mjs tests --tag A2.3`
2. Lancez-la pour de vrai sur une tâche :
   ```bash
   node guichet.mjs boucle taches/tronquer-resume.md
   ```
   À chaque tour, Claude (`claude -p`) réécrit le fichier « texte » de votre stack ; la garde et les tests de la tâche (tag `BOUCLE`) jugent ; en cas d’échec, leur sortie exacte est renvoyée au tour suivant. Trois tours au plus.
3. Combien de tours ? Lisez ce que la garde et les tests ont renvoyé.

Réussite : `node guichet.mjs verifier A2.3` · reprise : `node guichet.mjs reprise A2.3`

### A2.4 · Le juge (15 min)

1. Écrivez dans `prompts/juge.md` une grille d’au moins quatre critères (séparation des couches, gestion des erreurs, nommage, testabilité…).
2. `node guichet.mjs juger src/pipeline` (le chemin est résolu dans votre stack).
3. Notez vous-même les fichiers, puis comparez vos notes à celles du juge. Désaccord ? Corrigez la grille, pas le code.

Réussite : `node guichet.mjs verifier A2.4` · reprise : `node guichet.mjs reprise A2.4`

### A2.5 · Mini-évaluation (40 min)

```bash
node guichet.mjs eval --prompt extraction.v1 --modele haiku
node guichet.mjs eval --prompt extraction --modele haiku
node guichet.mjs eval --prompt extraction --modele sonnet
```

Chaque mesure s’ajoute à `eval/rapport.md` (score par champ, temps moyen, cas ratés). Puis :

1. Ouvrez les cas ratés : erreur du prompt, des règles, ou du jeu ?
2. Corrigez **une seule chose**, re-mesurez, notez l’écart.
3. Écrivez votre décision dans la section « Décision » du rapport.

Interdiction de retirer un cas du jeu de référence. En simulateur (`--moteur simu`), les réponses sont rejouées : les scores sont fixes, l’analyse reste valable.

Réussite : `node guichet.mjs verifier A2.5` · reprise : `node guichet.mjs reprise A2.5`

## Bonus

Ajoutez un 13ᵉ cas à `donnees/` qui piège votre meilleure version, et gardez-le.

## À retenir

Contraindre, vérifier, boucler, mesurer : le modèle peut se tromper, le système autour ne laisse pas passer l’erreur.
