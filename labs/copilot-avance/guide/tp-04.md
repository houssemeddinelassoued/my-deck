# TP 4 · Refactoring en profondeur avec votre agent Refactoreur

| 4 · Optimisation & refactoring | 25 min | Après-midi · vers 14:15 | `REFACTO.md`, `.github/agents/refactoreur.agent.md`, `.github/skills/refactoring-sur/` |

## Objectif

Optimiser le code du matin (SOLID, patterns, performance) avec **votre** agent personnalisé, sans changer le comportement : chaque refactoring prouvé par des tests inchangés.

## Point de départ

- L’API testée du TP 3, tous les tests au vert, tout commité.

## Étapes

1. **Rôle Ask** : anti-patterns et violations SOLID de votre code, dans `REFACTO.md`. Un rapport, aucune modification. Priorisez trois refactorings.
2. Écrivez la skill `.github/skills/refactoring-sur/SKILL.md` : vos gestes de refactoring en dix lignes.
3. Écrivez l’agent `.github/agents/refactoreur.agent.md` : quatre outils au plus, des règles vérifiables.
4. Choisissez **Refactoreur** dans la liste des rôles : un refactoring, les tests, un commit `refactor : …`. Trois fois.
5. Optimisez `findAvailableRooms` : mesurez avant (`bench/availability.*`), donnez la mesure et la cible à l’agent, mesurez après.

## Modèle à copier

```markdown
---
name: Refactoreur
description: Refactore SalleLibre par petits pas sûrs, sans changer le
  comportement. Ne corrige pas de bug, ne touche pas aux tests.
tools: ['read', 'search', 'edit', 'execute']
skills: ['refactoring-sur']
---
Tu es le Refactoreur de SalleLibre.
- Lance les tests avant et après chaque geste.
- Un refactoring à la fois ; test rouge : annule le geste.
- Aucune correction de bug pendant un refactoring : signale-le.
- Ne modifie jamais tests/.
- Termine par le diff résumé et le message de commit proposé.
```

## Livrable

- Rapport d’anti-patterns en rôle Ask, priorisé
- Refactoreur : 4 outils au plus, règles vérifiables
- Trois refactorings, un commit chacun, aucun fichier de test modifié
- Benchmark avant / après de la recherche de salles

## Pièges à observer

- « Applique SOLID » : un diff géant. Nommez le symptôme, le principe et la cible, un refactoring par demande.
- Des tests modifiés dans le même diff : ils ne prouvent plus que le comportement est préservé.
- `tools: ['*']` par confort : l’agent peut tout faire, y compris ce que vous n’aviez pas prévu.
- Optimiser sans mesurer : l’algorithme « plus malin » est parfois plus lent sur vos volumes.

## Bonus

Retirez `execute` de l’agent et relancez : que fait-il quand il ne peut plus lancer les tests ?

## Coincé ?

- Refactoreur n’apparaît pas dans la liste ? Vérifiez l’extension `.agent.md`, le dossier `.github/agents/`, puis **Chat: Open Customizations › Agents**.
- La skill n’est pas chargée ? Le nom dans `skills:` doit être exactement celui du dossier.
