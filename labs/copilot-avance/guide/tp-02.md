# TP 2 · Générer une API REST complète, guidée par vos instructions

| 2 · Modules & architectures | 30 min | Matin · vers 11:05 | `PLAN.md`, `.github/copilot-instructions.md`, `src/**`, `openapi.yaml` |

## Objectif

L’API SalleLibre fonctionne, guidée par **vos** règles de la maison écrites une fois : authentification JWT, CRUD des salles (admin), réservations sans chevauchement, validation, documentation OpenAPI.

## Point de départ

- Votre dépôt après le TP 1 : `overlaps` et ses tests.
- Persistance **en mémoire** : pas de base de données aujourd’hui, les tests restent rapides.

## Étapes

1. **Rôle Plan** : demandez l’arborescence (le rôle de chaque dossier en une ligne) et la liste des interfaces à créer en premier. Aucune implémentation. Validez, puis enregistrez le plan dans `PLAN.md`.
2. Écrivez `.github/copilot-instructions.md`, **40 lignes au plus** : la stack, les couches de `PLAN.md`, les erreurs métier et leurs codes HTTP, la règle des dépendances. `/init` dans une session d’agent peut proposer un premier jet : raccourcissez-le.
3. **Rôle Agent, lot par lot** : domaine (reprenez `overlaps`), repositories en mémoire, services. Un lot, ses tests, un commit.
4. Routes, validation, authentification, puis la documentation OpenAPI.
5. À chaque réponse, dépliez **Références** : votre fichier d’instructions doit y figurer. Une règle ignorée ? Corrigez le fichier, pas le prompt.

## Modèle à copier

```markdown
# SalleLibre · instructions pour Copilot
API REST FICTIVE de réservation de salles.
TypeScript, Express, Node.js 22 (adaptez à votre stack).

## Architecture (voir PLAN.md)
- domain/ pur : ni HTTP, ni stockage.
- Routes fines → services (règles) → repositories (interfaces).
- Erreur métier typée : ConflictError → 409, ForbiddenError → 403,
  jamais une erreur générique.

## Règles maison
- Aucune dépendance ajoutée sans mon accord.
- Toute entrée validée avant le service.
- Aucun secret dans le code : variables d’environnement.

## Tests
- Un test par règle métier ; ne jamais modifier tests/acceptance/.
```

## Livrable

- Plan validé dans `PLAN.md` avant toute ligne de code
- `copilot-instructions.md` (≤ 40 lignes) cité dans les Références
- 409 sur chevauchement, 401 sans jeton, 403 sans le bon rôle
- Documentation OpenAPI accessible et à jour

## Pièges à observer

- Tout générer en un seul prompt : un diff de 30 fichiers que personne ne relira.
- Un fichier d’instructions encyclopédique : chaque ligne se paie à chaque requête, et les règles utiles s’y noient.
- `copilot-instructions.md` **et** `AGENTS.md` qui se contredisent : Copilot combine les deux, sans priorité.

## Bonus

Transformez votre meilleur prompt du TP 1 en skill : `.github/skills/chevauchement/SKILL.md`, avec un en-tête `name: chevauchement`, une `description` et `disable-model-invocation: true`, puis votre prompt. Tapez `/chevauchement` dans le Chat.

## Coincé ?

- Les instructions n’apparaissent pas dans les Références ? Vérifiez le chemin exact (`.github/copilot-instructions.md`) et ouvrez **Chat: Open Customizations**.
