# TP 6 · Projet de clôture : une feature orchestrée

| 6 · Copilot en équipe | 25 min | Après-midi · vers 16:15 | `.github/agents/chef-orchestre.agent.md` (+ architecte, testeur, documentaliste), une PR |

## Objectif

Livrer une feature complète de SalleLibre (code, tests, documentation, sécurité) en orchestrant vos agents, et garder la main aux deux décisions : **le plan**, puis **le diff**. Deux ou trois volontaires présentent ensuite leur travail (4 minutes).

## Point de départ

- Votre dépôt du TP 5, avec `refactoreur.agent.md` et `auditeur.agent.md`.
- Les agents Architecte, Testeur et Documentaliste : collés dans le Chat (annexe D).
- Une feature au choix : **réservations récurrentes** (chaque mardi, avec exceptions), **liste d’attente** ou **export iCal**.

## Étapes

1. Copiez les trois agents fournis dans `.github/agents/`.
2. Écrivez `chef-orchestre.agent.md` : l’outil `agent`, la délégation par nom exact, et **deux points d’arrêt** (le plan, le diff).
3. Choisissez **Chef d’orchestre** dans la liste des rôles et décrivez la feature.
4. Quand il s’arrête : relisez le plan, corrigez-le si besoin, validez.
5. Suivez les sous-agents dans le Chat (appels repliés) : tests rouges, code, audit, documentation.
6. À la fin : relisez le diff **des tests** d’abord, puis celui du code. Ouvrez la PR avec une description.
7. Volontaire pour présenter ? 4 min : démo avec un sous-agent déplié, preuves, un refus argumenté.

## Modèle à copier

```markdown
---
name: Chef d’orchestre
description: Mène une feature de SalleLibre de bout en bout en
  déléguant aux agents spécialisés.
tools: ['agent', 'read', 'search', 'edit', 'execute', 'todo']
---
Tu coordonnes. Sollicite chaque agent comme sous-agent, par son nom exact.
1. Architecte : un plan en lots.
   ARRÊTE-TOI : j’approuve le plan.
2. Pour chaque lot :
   a. Testeur : les tests du lot, ROUGES.
   b. Toi : le code minimal, jusqu’au vert. Ne modifie aucun test.
   c. Auditeur : audit du diff. Faille bloquante : retour en a.
3. Documentaliste : OpenAPI et README.
4. Résume lots, tests, failles, risques restants.
   Je relis le diff avant la PR.
```

## Livrable

- Délégation par nom, deux points d’arrêt dans le chef d’orchestre
- Plan validé, tests rouges puis verts
- Audit du diff fait, failles traitées
- Diff des tests relu, PR décrite, CI verte

## Pièges à observer

- Oublier les points d’arrêt : l’agent enchaîne tout, et vous découvrez 20 fichiers modifiés.
- Un nom d’agent mal orthographié : la délégation échoue ou part vers un agent générique.
- Orchestrer une petite tâche : chaque sous-agent consomme des crédits. On n’orchestre pas une faute de frappe.
- Des `handoffs` copiés d’un ancien tutoriel : ignorés par le harnais Copilot.

## Bonus

Lancez la revue en parallèle : « Utilise Architecte, Testeur et Auditeur comme sous-agents, en parallèle, pour relire ma PR, puis fais la synthèse. »

## Coincé ?

- Le chef d’orchestre code tout lui-même ? Vérifiez qu’il a l’outil `agent` et que le corps nomme les agents exactement comme leur champ `name`.
- Plus que 10 minutes ? Réduisez la feature à un seul lot, mais allez jusqu’à l’audit et la PR.
