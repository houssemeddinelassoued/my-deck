# TP 1 · Réécrire des prompts basiques et mesurer

| 1 · Prompt engineering avancé | 20 min | Matin · vers 9:50 | `prompts/tp1-mesures.md`, `src/domain/overlap.*`, `prompts/meilleur-prompt.md` |

## Objectif

Prouver, chiffres à l’appui, qu’un prompt structuré produit un meilleur code qu’un prompt basique sur trois tâches de SalleLibre. Mesurer, pas ressentir.

## Point de départ

- Le dépôt `sallelibre`, vide, dans la stack de votre choix.
- Réglages : **session Copilot**, **rôle Agent**, et **un seul modèle** choisi dans la liste pour toutes les mesures (pas Auto : sinon vous comparez des modèles, pas des prompts).

## Les trois prompts de départ

- P1 · « fais une fonction qui vérifie si deux réservations se chevauchent »
- P2 · « génère les modèles de données de l’appli »
- P3 · « écris la fonction qui trouve les salles libres »

## Étapes

1. Créez `prompts/tp1-mesures.md` et fixez votre grille **avant** le premier essai : compile ? tests passent ? bornes correctes (10h–11h puis 11h–12h : pas de chevauchement) ? nombre d’allers-retours.
2. Lancez chaque prompt tel quel **deux fois**, chaque fois dans une **nouvelle session** (Ctrl+N dans la vue Chat). Notez la grille.
3. Réécrivez chaque prompt avec les cinq composants : contexte, tâche bornée, contraintes, exemples attendus, critère de fin (voir l’annexe B).
4. Relancez chaque version V2 deux fois en session neuve. Notez.
5. Gardez le code du meilleur résultat pour `overlaps` : c’est la première brique de SalleLibre.
6. Copiez votre meilleur prompt dans `prompts/meilleur-prompt.md` : il deviendra une skill au TP 2.

## Livrable

- Session Copilot, rôle Agent, un seul modèle pour toutes les mesures
- Trois prompts réécrits avec les cinq composants
- Chaque version lancée 2 fois en session neuve, grille remplie
- `overlaps` et ses tests commités, meilleur prompt conservé

## Pièges à observer

- Changer deux choses à la fois entre V1 et V2 : vous ne savez plus ce qui a fait la différence.
- Rester dans la même session : l’historique des essais précédents devient un contexte.
- Juger « à l’œil » : sans grille décidée avant, on retient le résultat qui nous arrange.

## Bonus

Relancez votre meilleur prompt avec un autre modèle : la grille bouge-t-elle plus d’un modèle à l’autre que d’un prompt à l’autre ?

## Coincé ?

- Les bornes sont toujours fausses ? Donnez l’exemple qui tranche dans le prompt : `[10:00, 11:00[` et `[11:00, 12:00[` ne se chevauchent pas.
- Le code part dans tous les sens ? Ajoutez le critère de fin : « Arrête-toi quand ces 4 exemples sont des tests verts. »
